# Contributing

## Practice workflow

1. Create an issue with a clear outcome and completion check.
2. Create a branch whose name describes the change.
3. Make the smallest change that completes the issue.
4. Commit with an imperative, scoped message.
5. Open a pull request against `main`.
6. Record how the change was verified.
7. Review when the risk or collaboration context calls for it.
8. Merge and remove the completed branch.

## Commit examples

```text
docs: clarify the pull request checklist
chore: add a reusable issue template
```

## Pull request quality checklist

- The title describes the outcome.
- The body explains the reason for the change.
- Verification is documented.
- Unrelated changes are excluded.
